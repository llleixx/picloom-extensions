# 本地 NSFW 审核

[English](README.md) · **简体中文**

使用随插件提供的 NSFWJS MobileNetV2 模型，在图片保存后审核色情、色情动漫及可选的性感内容。图片在 Picloom 服务器上通过 CPU 识别，无需 GPU、外部服务或凭据，运行时不下载模型、不将图片发送到第三方。

`picloom.nsfw-moderation` · `processor` · `post_save`

## 安装与使用

在插件管理中上传本插件 ZIP，创建配置，将其加入上传配置使用的保存后流水线。需要通知时，将 Telegram 通知等插件放在审核步骤之后。在图片详情中查看审核结果；命中后默认屏蔽，也可选择删除。

| 配置                         | 默认值           | 填写方式                                      |
| ---------------------------- | ---------------- | --------------------------------------------- |
| 检测类别 `categories`        | `Porn`、`Hentai` | 色情、色情动漫；可选性感内容 `Sexy`，至少一项 |
| 命中阈值 `threshold`         | `0.8`            | 大于 0、至多 1，所有选定类别共用              |
| 命中处置 `blockAction`       | `block`          | 屏蔽 `block` 或删除 `delete`                  |
| 最大抽帧数 `maxFrames`       | `5`              | 1–10；1 表示只审首帧                          |
| 文件读取上限 `maxContentMiB` | `20`             | 高级设置，1–100 MiB                           |
| 执行超时 `timeoutMs`         | `30000`          | 高级设置，1000–120000 毫秒                    |

任一被审核帧中，任一选定类别的分数达到阈值即命中，不累加不同类别分数。默认阈值是起始配置，不代表准确率；可根据实际图片的误判和漏检调整。默认不检测 `Sexy`，勾选后泳装、写真等图片也可能命中。

这是保存后审核，完成前图片可能已经可访问。已有屏蔽或删除决定不会被本插件的通过结果撤销。安装插件和修改配置不会自动重审已完成的图片。

## 图片范围与结果

通过 Picloom 提供的 Sharp 解码 JPEG、PNG、WebP、GIF、AVIF、TIFF 和 SVG；实际解码能力取决于宿主。单帧最多 4000 万像素。识别前校正方向、将透明区域合成白色，并转为 224×224 的 sRGB 图片；存储原图不变。SVG 仅审核静态栅格化画面。

多帧图片按帧序号均匀取样，包含首尾帧；不足上限时全部审核。例如 21 帧、上限 5 时取第 1、6、11、16、21 帧。帧时长不影响选择，未抽中的画面不在审核范围内。增加抽帧数会增加 CPU 消耗和耗时。

审核摘要包含模型、所选类别、阈值、各类别最高分、命中类别、总帧数和实际审核帧数。最高分可能来自不同帧，不是一组单帧概率。摘要中的 `Drawing`、`Neutral` 仅用于展示，不参与违规判定。

超限、解码失败、模型加载失败、无效输出和超时会记录任务错误，不算审核通过，也不会自动屏蔽图片；这些错误不自动重试。Worker 意外退出允许核心按任务规则重试；文件读取错误沿用宿主的重试规则。修复原因后可通过现有任务入口重试。

每个运行实例串行审核并复用模型，首次执行需要加载模型。超时从取得执行名额开始计时，覆盖模型加载、文件读取、解码和推理；队列等待不计入超时。删除文件或销毁实例会取消相关执行，后续执行可重新加载模型。

## 开发

使用仓库指定的 Bun，在仓库根目录安装依赖后，进入本目录：

```sh
bun run typecheck
bun run test
bun run build
```

这些命令先生成 `.generated/worker.ts`，将 CPU 推理代码和唯一的 MobileNetV2 模型嵌入插件，再由公共插件工具打包。ZIP 可独立安装，无需目标服务器安装 npm 依赖。生成文件不提交。

测试包括模拟分数的处置测试、真实 GIF/WebP 抽帧、取消与失败处理，以及禁用网络的真实模型测试；这些测试不证明识别准确率。可运行 `bun scripts/verify-package.ts` 验证已构建 ZIP 的独立加载、离线推理和资源释放，并输出本机耗时、内存及包大小。若指定 `PICLOOM_SOURCE_DIR`，还会使用该源码的临时测试环境安装插件并执行保存后流水线，不接触预览数据。

模型来自 [NSFWJS](https://github.com/infinitered/nsfwjs)，推理使用 [TensorFlow.js](https://github.com/tensorflow/tfjs)。安装包的 `thirdPartyNotices` 导出包含依赖许可证；`licenses/` 中保留 npm 包未附带的 Apache 2.0 文本及 TensorFlow.js Layers 双许可证，后者取自上游对应版本。
