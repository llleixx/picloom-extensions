# 本地 NSFW 审核

[English](README.md) · **简体中文**

使用随插件提供的 NSFWJS MobileNetV2 模型，在服务器 CPU 上审核色情、色情动漫及可选的性感内容。无需 GPU、外部服务或凭据，运行时不下载模型、不将图片发送到第三方。

`picloom.nsfw-moderation` · `processor` · `post_save`

## 开始使用

按[安装插件](https://llleixx.github.io/picloom/guide/plugins.html)安装 ZIP，在 **配置 → 流水线** 的保存后阶段添加本插件，选择类别、阈值和处置，并将流水线关联到上传配置。

上传测试图片，在图片详情查看审核结果。命中后默认屏蔽，也可选择删除；需要通知时，将通知插件放在审核步骤之后。

## 配置

| 字段 | 含义 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| `categories` | 检测类别 | 是 | `Porn`、`Hentai` | 色情、色情动漫；可选性感内容 `Sexy`，至少一项 |
| `threshold` | 命中阈值 | 是 | `0.8` | 大于 0、至多 1，所选类别共用 |
| `blockAction` | 命中处置 | 是 | `block` | 屏蔽 `block` 或删除 `delete` |
| `maxFrames` | 最大抽帧数 | 是 | `5` | 1–10；1 表示只审首帧 |
| `maxContentMiB` | 文件读取上限，MiB | 是 | `20` | 高级设置，1–100 |
| `timeoutMs` | 执行超时，毫秒 | 是 | `30000` | 高级设置，1000–120000 |

## 行为与限制

任一抽样帧的任一选定类别达到阈值即命中，不累加不同类别分数。阈值不代表准确率，应结合误判和漏检调整；启用 `Sexy` 后，泳装、写真等也可能命中。本插件的通过结果不会撤销已有屏蔽或删除决定。公开访问时机、累计处置和配置生效范围见[保存后流水线](https://llleixx.github.io/picloom/guide/pipelines.html)。

静态图审核一帧；GIF、动态 WebP 等多帧图片按帧序号均匀取样，包含首尾帧，不足上限时全部审核。例如 21 帧取 5 帧时，审核第 1、6、11、16、21 帧。帧时长不影响选择，未抽中的画面不在审核范围内；增加抽帧数会增加 CPU 消耗和耗时。

格式支持取决于宿主 Sharp 的解码能力，单帧最多 4000 万像素。识别前校正方向、将透明区域合成白色并转为 224×224 sRGB 图片；原图不变。SVG 仅审核静态画面。

摘要记录模型、类别、阈值、各类别最高分、命中类别、总帧数和实际审核帧数。最高分可能来自不同帧；`Drawing`、`Neutral` 仅展示，不参与判定。

超限、不支持的格式、解码或模型加载失败、无效输出和超时会记录任务错误，不算审核通过，也不会自动屏蔽或重试。Worker 意外退出和文件读取错误沿用宿主重试规则；修复原因后可在后台任务中重试。

每个实例串行审核并复用模型，首次执行加载模型。超时覆盖模型加载、读取、解码和推理，不含排队等待。删除文件或销毁实例会取消相关执行，后续执行可重新加载模型。

## 开发

通用命令见[仓库开发说明](../../README.zh-CN.md#开发与验证)。本插件的类型检查、测试和构建会先生成 `.generated/worker.ts`，将 CPU 推理代码和 MobileNetV2 模型嵌入 ZIP；生成文件不提交，安装时无需额外 npm 依赖。

构建后在本目录运行 `bun scripts/verify-package.ts`，验证 ZIP 独立加载、离线推理及资源释放，并输出耗时、内存与包大小。设置 `PICLOOM_SOURCE_DIR` 可同时验证临时宿主中的安装及保存后流水线，不接触预览数据。模拟分数测试验证处置规则，真实模型测试验证运行链路，均不证明识别准确率。

模型来自 [NSFWJS](https://github.com/infinitered/nsfwjs)，推理使用 [TensorFlow.js](https://github.com/tensorflow/tfjs)。安装包的 `thirdPartyNotices` 导出包含依赖许可证；`licenses/` 中保留 npm 包未附带的 Apache 2.0 文本及 TensorFlow.js Layers 双许可证，后者取自上游对应版本。
